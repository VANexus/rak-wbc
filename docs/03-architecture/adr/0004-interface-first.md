# ADR 0004: 接口优先，先定 `rak_wbc_msgs`

- 状态：Accepted
- 日期：2026-10-21

## 背景

多人/多包并行开发时，最容易出现的问题是各自定义私有消息、话题命名不一致、
时间戳/frame 约定不同，导致集成阶段大量返工。

## 决策

1. 所有跨包通信优先使用 `rak_wbc_msgs`：
   - `RobotStatus`（比赛状态码）
   - `ContactState`（接触/打滑/CoP）
   - `Footstep` / `FootstepArray`
   - `MotionPrimitive`
   - `SetMotionPrimitive`
   - `ExecuteTask`
2. 话题/服务/Action 命名、频率、QoS 在 `docs/03-architecture/system-architecture.md` 统一登记。
3. 任何接口变更必须先改消息定义 + 更新架构文档，再改实现。
4. 包内允许有私有类型，但不得跨包发布/订阅。

## 后果

### 正面

- 并行开发有稳定契约；集成成本低。
- 比赛状态码、日志字段、裁判遥测字段统一。
- 便于生成文档/可视化/回放工具。

### 负面

- 早期需要花时间设计接口；可能过度设计。
- 消息变更需要全链路同步。

## 备选方案

1. **各包自定义**：最快开始，集成最痛。
2. **只用标准消息**：表达力不足（状态码/接触/运动基元需要自定义）。
3. **大而全的单一消息**：耦合高，演进困难。
