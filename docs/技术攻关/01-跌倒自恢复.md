# 技术攻关 ① 跌倒自恢复

> **为什么这是第一优先级**：5.3 稳定性 6 分明文规定"摔倒后**无法**自恢复或需外力得 **0 分**"，
> 且判据针对**全程**——一次需外力就归零。再叠加"人工干预 −2 + 任务降档 −5 + 自主等级 16→10 的 −6"，
> 单次无法自恢复的摔倒代价高达 **−19 分**。
>
> 而可行性上：**平地上"≤3 s 自主起身"在 2025–2026 已经是可复现的水平**，不是研究前沿。

---

## 一、SOTA 现状（别人做到哪了）

| 工作 | 时间 | 方法 | 关键结论 | 对我们的价值 |
|---|---|---|---|---|
| **HUMANUP**（UIUC, He et al., arXiv 2502.12152） | 2025-02 | **两阶段 RL + sim2real** | **真机 Unitree G1 从仰卧起身、从俯卧翻滚** 已实现 | ⭐ **直接可复刻的路线图** |
| **HOST**（Humanoid Standing-up Control） | 2025 | RL 框架，跨姿态起身 | ⚠️ **俯卧与仰卧一起训练会互相干扰、降低效果** | ⭐ 决定"要不要分开训" |
| **FRASA**（Gaspard et al., arXiv 2410.08655） | 2024-10 | 端到端 RL，跌倒恢复 + 起身 | 一体化 agent | 参考 |
| 四足跌倒恢复 RL（MDPI Actuators 2023） | 2023 | RL + 动态恢复 | 完全跌倒后可翻转恢复；**恢复过程最大角速度 10 rad/s** | ⚠️ 注意我们受 6.2.1 限制，不能这么快 |
| Digit（Agility）自起身 | — | 工业实现 | 商用机器人已具备自起身 | 说明工程上已成熟 |

### 1.1 三条最重要的共识

**共识 1：把"起身"分解，不要指望单一策略覆盖所有姿态。**
He et al. 的做法是把"俯卧起身"分解为 **翻滚(roll over) → 变成仰卧 → 从仰卧起身**，
两个子策略分别训练。HOST 独立观察到"俯卧+仰卧混合训练会因 rollout 相互干扰而降低性能"。

**共识 2：两阶段训练——先找到解，再把它变"温和"。**
- Stage I：**最小约束**下找到有效肢体轨迹（允许大幅度、快速动作）。
- Stage II：在**控制正则化**（动作幅度/速率惩罚）下跟踪 Stage I 得到的轨迹，
  并在**多样的初始姿态与地形**上训练。

> ⭐ **Stage II 的"控制正则化"正好命中我们的合规需求**：6.2.1 要求
> "失控触发急停后，关节缓慢卸力，**禁止剧烈甩动**"。学术界做 Stage II 是为了动作自然，
> 我们做 Stage II 是**为了合规 + 保护硬件**。目标一致，可以直接复用这套设计。

**共识 3：必须显式建模硬件约束。**
HOST 对前人的批评原文就是"要么忽略硬件约束，要么依赖预先定义的、特定地面的运动轨迹"。
→ 我们的策略训练里**必须包含硬件约束惩罚**，否则学出来的动作会撞关节限位、自碰撞、烧电机。

## 二、我们的方案：RL 生成动作 + FSM 管安全与时延

### 2.1 整体架构（混合式，不是纯 RL）

```
┌────────────────────────── 监督层 FSM（确定性、可验证）──────────────────────────┐
│  IDLE → DETECT(姿态阈值+触地) → CLASSIFY(俯卧/仰卧/侧翻) → SELECT_POLICY        │
│       → EXECUTE(调用 RL 策略) → 进度检查(100ms)                                │
│            ├─ 正常 → 继续                                                      │
│            ├─ 卡住 → RETRY(换策略/换子任务) 最多 N 次                          │
│            └─ 已站立 → STABILIZE(站立 1s) → 上报 NORMAL_WALK                   │
└───────────────────────────────────┬────────────────────────────────────────────┘
                                    ↓ 关节目标 / 动作
┌────────────────────────── 执行层 RL 策略（学习）──────────────────────────────┐
│  俯卧翻滚策略  │  仰卧起身策略  │  侧翻起身策略      （3 个独立策略）          │
│  输入：本体感知（IMU + 关节位置 + 足底力）  ← 不依赖视觉！                     │
│  输出：关节目标（位置模式，频率 50–100 Hz）                                    │
└───────────────────────────────────────────────────────────────────────────────┘
```

**为什么是混合式而不是纯 RL**：
- RL 负责"怎么动"（它擅长），FSM 负责"什么时候动、超时怎么办、要不要重试、如何上报状态"（确定性，可验证、可测试）。
- 5.3 的 **3 秒** 是硬指标 → 必须能**测量、复现、调试**。纯 RL 的失败模式难以定位；
  FSM 可以把"检测慢""分类错""策略卡住"三类失败分开统计和优化。

### 2.2 三个策略 + 一个"无视觉"原则

| 策略 | 覆盖姿态 | 说明 |
|---|---|---|
| P1 俯卧翻滚 | prone | 俯卧 → 侧身 → 仰卧 |
| P2 仰卧起身 | supine | 仰卧 → 坐起 → 蹲 → 站 |
| P3 侧翻起身 | lateral | 侧卧 → 仰卧/俯卧 → 接 P2/P1 |

**⚠️ 关键原则：不用视觉。** 跌倒时相机可能被身体压住、朝向地面、或被遮挡。
用 **IMU（躯干姿态）+ 关节编码器 + 足底力** 就能完成姿态分类与执行 →
视觉失效时仍可恢复。这同时满足了"单传感器失效仍可工作"的鲁棒性要求。

### 2.3 姿态分类判据（供 FSM 使用）

用躯干姿态的**重力方向在机体系下的投影**做粗分类（无需视觉）：

| 判据 | 姿态 |
|---|---|
| 重力 −Z 方向指向机器人腹部（躯干 pitch 超阈值） | 俯卧 prone |
| 重力方向指向背部 | 仰卧 supine |
| 重力方向横向指向躯干侧面 | 侧卧 lateral |
| 足底力 > 阈值 且 躯干接近直立 | 已站立 |

> 注意：**只用姿态分类，不追求精细**。分类错误时 FSM 会通过"进度检查失败 → RETRY 换策略"自动纠偏。
> 这比追求 100% 分类准确率更稳健。

## 三、训练配方（可直接执行）

### 3.1 Stage I：找解

| 项 | 设置 |
|---|---|
| 仿真 | Isaac Lab（G1 或 T1 的 USD） |
| 算法 | PPO（rsl-rl），并行 env 4096 |
| 动作空间 | 关节位置目标（**不要**直接输出力矩——位置模式更稳、更易 sim2real） |
| 初始状态 | 从**姿态分布**采样（俯卧/仰卧/侧翻 各家族内随机：躯干俯仰/横滚、关节构型、离地高度） |
| 地形 | 平地起步；随后加入坡度、碎石高度噪声 |
| 奖励（示意） | ① 躯干高度/直立度 ② 头部/躯干目标高度 ③ 成功站立奖励 ④ 关节速度惩罚（**弱**，Stage I 允许快） ⑤ 自碰撞惩罚 ⑥ 关节限位惩罚 ⑦ 足底接触目标 |
| 关键：**必须加** | **自碰撞惩罚 + 关节限位惩罚 + 力矩上限惩罚**（HOST 的核心批评点） |

### 3.2 Stage II：变温和、变鲁棒

| 项 | 设置 |
|---|---|
| 初始化 | 从 Stage I 策略开始（**不是从零**） |
| 新增目标 | **跟踪 Stage I 得到的关节轨迹**（reference tracking），而不是自由探索 |
| **控制正则化** | 加大关节速度/加速度惩罚；加**动作速率限制**（`|Δq| ≤ q̇_max·Δt`，对齐 6.2.1"禁止剧烈甩动"） |
| 初始状态 | **更多样的初始姿态 + 更多样地形**（平地/斜坡/碎石/台阶上） |
| 对齐目标 | ⭐ 让恢复动作"**慢而稳**"，同时保持成功率 |

> **Stage II 的产物同时满足两个目标**：学术界要的"动作自然"，我们要的"符合 6.2.1 + 保护硬件"。
> 一举两得，这条是本文档最有价值的复用点。

### 3.3 域随机化（起身专用）

| 随机化项 | 范围 | 理由 |
|---|---|---|
| 初始姿态 | 全姿态空间采样 | 真实摔倒姿态不可控 |
| 地面坡度 | 0–15° | 4.2 斜坡 10–15° |
| 地面高度噪声 | 0–30 mm | 4.2 碎石 10–40 mm |
| 摩擦系数 | 0.3–1.2 | 碎石/湿滑 |
| 关节力矩/延迟 | ±15% / 0–10 ms | 驱动器差异 |
| 机身质量/质心 | ±10% | 装配差异 + 载具残留 |
| **负载残留** | 0–2 kg（手持物未放下时摔倒） | 实况可能带物摔倒 |
| IMU 噪声/偏置 | 实测标定值 ±20% | 状态估计误差 |

> **最后两项容易漏**：实况中机器人可能**手里还拿着东西**摔倒（任务 3/5 中），
> 也可能**抱假人时摔倒**（任务 4）。训练时不覆盖，真机就会失败。

## 四、时延预算（3 秒怎么分配）

5.3 明文 **3 秒内**。我们把预算拆开，留 33% 余量到 2 s：

| 阶段 | 预算 | 说明 |
|---|---|---|
| 1. 跌倒检测 | ≤ **150 ms** | IMU 姿态突变 + 足底力丧失 + 高度骤降，三判据取或 |
| 2. 稳定（停止抖动，确认已静止） | ≤ **200 ms** | 惯性未收敛不能开始起身，否则动作失准 |
| 3. 姿态分类 | ≤ **50 ms** | 查表/阈值，极快 |
| 4. 策略推理首帧 | ≤ **50 ms** | 小 MLP，50–100 Hz，单帧推理 <10 ms；含调度开销 |
| 5. **动作执行** | ≤ **1200 ms** | 主体；Stage II 正则化后动作变慢，这里要专门优化 |
| 6. 稳定站立确认 | ≤ **300 ms** | 站立稳定 1 s 的判据中，前 300 ms 用于确认 |
| **合计设计值** | **≈ 1950 ms** | 余量 1050 ms |

**⚠️ 摩擦点**：Stage II 的"慢动作"与"3 秒指标"是**此消彼长**的。
→ 优化方向：**让动作慢但路径短**（减少多余的调整/试探动作），
而不是"为了让动作慢而拖长"。这需要 Stage II 的奖励里同时压 **动作速率** 和 **总时长**。

> 建议：把"总时长"作为 Stage II 的显式惩罚项，并做 **Pareto 扫描**
> （成功率 vs 耗时），选取"成功率 ≥95% 且耗时 ≤2 s"的工作点。**不要**用"最慢最安全"的点。

## 六、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **RL 起身动作过猛** | 违反 6.2.1、损伤关节、摔得更狠 | Stage II 动作速率上限（硬约束，不只是惩罚项） |
| 起身时自碰撞 | 撞坏灵巧手/相机 | 自碰撞惩罚 + 硬约束投影 |
| **负重/持物状态下摔倒** | 训练未覆盖 → 真机失败 | 域随机化加"负载残留 0–2 kg" |
| 斜坡上起身滑落 | 反复失败 → 超时 → 可能触发干预 | 斜坡专用：先"制动"再起身；斜坡随机化 |
| 起身过程中再次摔倒 | 5.3 摔倒次数预算只有 2 次 | 起身策略里加"中间稳定姿态"检查点，不稳则回退 |
| 单策略覆盖多姿态效果差 | 成功率低 | 按 HOST 结论：**俯卧/仰卧分开训**，用 FSM 调度 |

## 七、⭐ 反向思考：降低摔倒概率的 ROI 高于提升恢复速度

算一笔账：

- 摔倒次数预算只有 **2 次**（第 3 次稳定性 0 分）。
- 每次摔倒都有"恢复失败"的概率。

设：单次恢复成功率 p，一轮摔倒 n 次，则"稳定性满分"概率 ≈ p^n。

| p | n=0 | n=1 | n=2 | n=3 |
|---|---|---|---|---|
| 0.90 | 100% | 90% | 81% | 73%（已超预算） |
| 0.99 | 100% | 99% | 98% | 97% |

→ **p=0.9 时哪怕只摔 2 次，稳定性满分的概率也只有 81%。**
→ 而"**一次都不摔**"直接把这个问题消掉。

**所以真正的优先级是：**
1. **先降低摔倒概率**（感知式运动 + 负载鲁棒策略，见 `技术攻关 ②`）—— 这是主力
2. **再提升恢复成功率与速度**（本文档）—— 这是保险

两者都要做，但**资源分配应该是"降摔 : 恢复 ≈ 7 : 3"**，而不是反过来。
很多队伍会本能地把精力全押在"摔倒后怎么爬起来"，这是次优的。
