# 技术攻关 ② 感知式运动与 sim2real

> **目标**：让机器人在 **碎石 / 连续斜坡 / 台阶 / 跨障栏 / 颠簸路面** 上稳定行走，
> **负重时也不摔**，且**跨主体 lap 到真机**。
> 这是 5.3 稳定性 6 分 + 任务 1 密林穿越 12 分 + 时间表现分的共同基础。

---

## 一、SOTA：已经有一个几乎照着抄的模板

### 1.1 ⭐ RPL（arXiv 2602.03002）—— 本赛道的对位方案

RPL 的关键事实（**在 Unitree G1 上真机验证**）：

- **两阶段框架**：
  - **Stage 1**：用 **privileged height map（特权高度图）** 训练**地形专用专家策略**
    —— 斜坡、上台阶、下台阶、踩石块，各训一个专家。
  - **Stage 2**：把多个专家**蒸馏（distill）成一个统一的、基于深度的策略**（depth-based transformer policy）。
- **真机验证的地形**：20° 斜坡、**台阶（步长 22 / 25 / 30 cm）**、**梅花桩 25×25 cm、间隙 60 cm**。
- **真实建筑楼梯**：单级高 **20 cm**、步长 **30 cm**，且是**弯楼梯**（需要转向 + 非零角速度）。
- **关键能力：双向行走（包括倒退）+ 负重时仍鲁棒**。
- 机器人**单脚长约 21 cm** → 在窄踏面上支撑面积有限，落脚精度要求高。

> ⭐ **这份工作几乎逐条命中我们的障碍清单和评分条款**：
> 斜坡（4.2-2）、台阶（4.2-3）、梅花桩（4.2-7）、**负重**（5.2 任务 4）、
> **双向行走**（出界后要"退回最近标记点"，见 4.4）。
> **结论：直接采用 RPL 的两阶段教师–学生蒸馏框架作为技术主线。**

### 1.2 落脚惩罚：两种，要按障碍分派（重要细节）

RPL 给出了一个非常实用的工程结论——**"落脚惩罚"的类型要按地形选**：

| 地形 | 用哪种惩罚 | 原因（原文） |
|---|---|---|
| **台阶** | **foothold penalty（落脚点惩罚）** | 台阶踏面很窄（0.25 m 台阶 vs 0.21 m 脚），
如果按"脚边缘膨胀"来做，有效落脚区几乎消失 |
| **踩石块/梅花桩** | **foot-edge penalty（脚边缘惩罚）** | 石块小且孤立，容错低；
用落脚点惩罚会允许"脆弱的边界接触"，被动作噪声放大成失稳 |

> 这是"论文里才有、工程上很值钱"的细节。直接映射：
> - **台阶（4.2-3）→ foothold penalty**
> - **跨障栏（4.2-4）/ 梅花桩 / 浅坑（4.2-7）→ foot-edge penalty**
> - **碎石（4.2-1）→ 不做落脚点规划，改做"粗糙度代价 + 阻抗式落脚"**

### 1.3 其他可用工作

| 工作 | 用途 |
|---|---|
| **HUGWBC**（RSS 2025，有开源代码） | 统一通用全身控制器；支持细粒度步态指令（步频、步高、站姿等），支持跳跃/站立/跳步；可直接作为**基线控制器** |
| Jenelten & Hutter 等：*Perceptive Locomotion in Rough Terrain – Online Foothold Optimization* | **在线落脚点优化**在 elevation map 上的经典方法，层级式规划器，可处理台阶 |

| Sim-to-Real Policy Transfer（Isaac Lab 官方流程） | ① 训 teacher（用特权信息）→ ② 蒸馏 student（去掉特权项）→ ③ 用 RL 微调 student |

## 二、⚠️ 一个必须先定的技术决策：LiDAR 还是深度相机做高度图？

**这是本赛道最容易被忽略、但可能决定成败的决策。**

4.3 说环境光照是"**普通室内 / 户外自然光，无强制补光**"。

| 传感器 | 室内 | **户外自然光** | 结论 |
|---|---|---|---|
| 结构光深度相机 | 好 | ❌ **强阳光直接失效**（红外图案被太阳淹没） | 不可单独依赖 |
| 主动双目（RealSense D435i 等） | 好 | ⚠️ **明显退化**（阳光下有效距离与精度大幅下降） | 不可单独依赖 |
| **3D LiDAR**（如 Livox Mid-360） | 好 | ✅ **不受环境光影响** | ⭐ **主用** |
| 被动双目（自然纹理） | 一般 | 尚可但受纹理/曝光影响 | 辅助 |

> ### 结论：**以 LiDAR 为主做地形高度图，深度/双目为辅。**
> 理由：
> 1. LiDAR 不受阳光影响，符合 4.3 的"户外自然光"。
> 2. RPL 的 G1 平台也提到了 **LiDAR-based elevation** 这一路。
> 3. 2.1 里 LiDAR 是"可选"，但**在这个光照条件下它实质上是必需品**。
> 4. LiDAR 同时解决 GNSS 遮挡区的定位（SLAM），一石二鸟。
>
> 💡 **如果赛道确认在室内 → 深度相机够用，可省成本；只要有任何户外可能 → 必须上 LiDAR。**
> 这条应作为"赛道是否室内"的**采购前置条件**。

## 三、我们的训练配方

### 3.1 总体流程（教师–学生蒸馏，四步）

```
Step 1  特权专家训练（Stage 1）
        输入：特权高度图（仿真直出的地形真值）+ 本体感知
        输出：4 个地形专家
              ├ E1 斜坡专家       （4.2-2: 10–15° 上坡 + 下坡）
              ├ E2 台阶专家       （4.2-3: 3–5 级；ftoothold penalty）
              ├ E3 石块/跨障专家   （4.2-4 跨障栏 60–100mm；4.2-7 梅花桩；foot-edge penalty）
              └ E4 崎岖/颠簸专家   （4.2-1 碎石；4.2-5 凹凸路面）
                    ↓
Step 2  蒸馏（Stage 2）
        学生输入：LiDAR 高度图 + 深度 + 本体感知历史（**无特权信息**）
        学生输出：统一策略（覆盖全部地形 + 双向行走 + 负重视角）
        方法：DAgger 式蒸馏 / 行为克隆 + RL 微调（Isaac Lab 官方三步法）
                    ↓
Step 3  鲁棒化
        - 域随机化（见 3.3）
        - 步态指令条件化（速度/朝向/步高/站姿）→ 供上层 L3 规划调用
        - 负重随机化（重点！见 3.4）
                    ↓
Step 4  部署
        TorchScript / ONNX 导出 → TensorRT → 机上 200–500 Hz（策略本身）；10–30 Hz（高度图）
```

### 3.2 为什么用"专家 → 蒸馏"而不是"一步到位训一个大策略"

| 方案 | 优点 | 缺点 |
|---|---|---|
| 直接训统一策略 | 实现简单 | 跨地形 interference（和 HOST 在起身任务上观察到的同源问题）；难调 |
| **专家 → 蒸馏** | 每类地形可独立收敛、可单独调参、可**针对性地形加权**；蒸馏后仍统一部署 | 工程量大、多一个蒸馏环节 |

> RPL 的真机结果证明"专家→蒸馏"在**斜坡+台阶+梅花桩+负重+双向**这个组合上是 work 的。
> 我们面对的地形清单更简单（且没有 60 cm 梅花桩间隙那么极端），**可行性有充分保障**。

### 3.3 域随机化清单（运动专用）

| 类别 | 项 | 范围 |
|---|---|---|
| **地形** | 高度噪声 | 0–30 mm（碎石 10–40 mm） |
| | 坡度 | 0–15°（含侧向坡） |
| | 台阶高/步长 | 台阶高 0–120 mm、步长 0.2–0.35 m |
| | 跨障栏高 | 0–100 mm |
| | 摩擦 | 0.3–1.2 |
| **本体** | 质量/质心/惯量 | ±10% |
| | 关节摩擦/延迟 | ±15% / 0–10 ms |
| | 关节零位偏差 | ±0.5° |
| | 电机力矩上限 | ±10% |
| **感知** | IMU 噪声/偏置 | 实测 ±20% |
| | LiDAR 高度图噪声 | 高度 ±20 mm、漏点率 0–10% |
| | 高度图延迟 | 0–100 ms（**重要**：真实高度图有延迟） |
| **指令** | 速度指令 | 0–1.5 m/s |
| | 指令延迟 | 0–50 ms |
| **扰动** | 外部推力 | 0–40 N，随机方向 |
| | 随机负载 | 见 3.4 |

> ⚠️ **"高度图延迟 0–100 ms"和"漏点率"是最容易漏的两项**。
> 真机上高度图不会像仿真那样"当前帧就到"；策略若对延迟敏感，真机就会震荡。

### 3.4 ⭐ 负重随机化（直接决定任务 4 能否得分）

5.2 任务 4 要求"抱起假人并顺利通过指定赛道"。策略必须**在训练时就知道负载的存在**。

| 项 | 随机化范围 |
|---|---|
| 负载质量 | **0 → 最大臂载**（按平台实测值，如 0–5 kg）全覆盖 |
| 负载质心位置 | 躯干前方 0.1–0.4 m，高度 ±0.15 m |
| 负载是否为动态（晃动） | 加柔性/阻尼连接模型（假人是软的，会晃） |
| 负载施加时机 | 任务中途施加（模拟"抱起"瞬间） |
| 负载移除 | 中途移除（模拟"掉落"）→ 要有**不失稳**的响应 |

> **RPL 已验证"remains robust with carried payloads"**，说明这条路可行。
> 但 RPL 的负载没说是"动态晃动"的假人 → **我们比它更难，必须把假人的柔性晃动建模进去**。
> 否则抱起后走路会因负载摆动而失稳。

### 3.5 奖励设计避坑（来自真实训练日志）

Isaac Lab 社区（NCRC 2026 高中竞赛，H1/Go2，4096 env，PPO/rsl-rl）总结出的高频失败模式：

> **`feet_air_time`（足部腾空时间）权重一旦超过 ~0.3，就会出问题。**

原因：这个奖励鼓励"抬脚久"，权重过大时策略学会了**长时间悬空/拖步**，破坏步态节奏。
→ 建议：`feet_air_time` 权重 ≤0.2，且配合"接触相位跟踪"奖励一起用。
→ 我们附加：**跨障栏（60–100 mm）需要足部腾空**，所以这项奖励确实有用，
但要**用"摆动足高度轨迹跟踪"代替"裸腾空时间"** 更可控。

## 四、地形高度图 → 可通行代价（衔接 L1/L3）

| 地形 | 提取特征 | 代价项 | 上层动作 |
|---|---|---|---|
| 碎石 10–40 mm | 粗糙度（邻域高度方差） | 高粗糙度 → 降速、提高步高 | 阻抗式落脚 + 降速 |
| 斜坡 10–15° | 平面拟合坡度/坡向 | 坡度 > 阈值 → 不可通行 | 沿等高线行走；下坡降速 |
| 台阶 3–5 级 | 高度不连续 + 踏面深度 | 台阶高 > 越障能力 → 不可通行 | **foothold penalty** 规划落脚 |
| 跨障栏 60–100 mm | 局部凸起高度 | 高度 → 抬腿高度指令 | **foot-edge penalty** |
| 颠簸木板/垫块 | 高度起伏 + 边缘 | 边缘 → 落脚避开 | 落脚点规划 |
| 浅坑 / 台阶段 | **负向**不连续 | ⚠️ **显式标为跌落风险，不插值** | 严禁踩入 |

> ⚠️ **负向不连续（洞）必须显式建模**。高度图若对台阶边缘做插值平滑，
> 机器人会把"前方是空的"读成"前方是缓坡"，然后踩空摔倒。
> 这是我们和很多开源实现的分水岭。

## 五、Sim2real 验收门槛

| 能力 | 仿真指标 | **真机门槛** | 仿真→真机折损容忍 |
|---|---|---|---|
| 平地速度 | 1.5 m/s | ≥1.0 m/s | 67% |
| 越障高度 | 150 mm | ≥120 mm | 80% |
| 坡度（上/下） | 20° | ≥18° | 90% |
| 台阶 | 5 级 / 150 mm | 4 级 / ≥120 mm | 80% |
| 跨障栏 | 120 mm | ≥100 mm | 83% |
| 碎石（40 mm） | 稳定 | 稳定 | — |
| 双向行走 | 稳定（含倒退） | 稳定 | — |
| **负重行走（最大载重）** | 稳定 | 稳定 | — |
| 跌倒恢复 | 1.5 s | **≤3 s** | 50% |

> **折损容忍度参考经验值 70–80%**。所以仿真目标必须显著高于真机门槛，
> 否则"仿真过了"但真机不过。

### 5.1 Sim2real 必做清单

- [ ] 关节零位标定（真机 vs 仿真）
- [ ] 电机力矩-电流曲线标定（这是最常见的 sim2real gap 来源）
- [ ] 关节摩擦/阻尼辨识
- [ ] 机身质量与惯量实测（称重 + 摆测试）
- [ ] IMU 噪声与偏置标定（静态 + 动态）
- [ ] LiDAR/相机外参标定 + 时间同步
- [ ] **高度图管线延迟实测**（喂进仿真）
- [ ] 通信延迟实测（观测 → 策略 → 关节指令的端到端延迟）
- [ ] sim-to-sim 验证（Isaac Sim ↔ MuJoCo 交叉验证，排除仿真器偏置）
- [ ] 真机分阶段：吊架/扶手 → 平地 → 低难度地形 → 全地形

> **"sim-to-sim 交叉验证"被 Isaac Lab 官方流程列为关键步骤**，但很多队伍会跳过。
> 在 MuJoCo 里复现一遍策略，能提前发现"其实是仿真器给了你不该有的信息"。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| **户外强光下深度相机失效** | **LiDAR 为主**；赛道是否室内列为采购前置问题 |
| 高度图延迟导致震荡 | 延迟随机化（0–100 ms）+ 观测历史窗口 |
| 负重后失稳 | 负载全域随机化 + 柔性晃动建模 |
| 碎石上路滑 | 摩擦随机化 0.3–1.2 + 打滑检测（足底力） + 阻抗式落脚 |
| 下坡前倾失稳 | 下坡专项训练（RPL 的双向行走覆盖下坡与倒退） |
| 专家蒸馏后能力退化 | 蒸馏后用 RL 微调（Isaac Lab 三步法第 3 步）；逐地形回归测试 |
| `feet_air_time` 权重过大导致拖步 | 权重 ≤0.2，改用摆动足高度轨迹跟踪 |
| **弯楼梯/转向** | RPL 的真机场景就是**弯楼梯**（20cm 高/30cm 长）→ 必须训转向 + 非零角速度 |
