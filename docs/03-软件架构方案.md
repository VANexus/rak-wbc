## 一、总体架构（感知–规划–控制 五层 + 两个横切）

```
┌──────────────────────────────────────────────────────────────────────────┐
│  L5  任务编排 Task Orchestration        (1–5 Hz, CPU)                     │
│      任务状态机 / 时间预算 / 降级策略(永不放弃) / 打卡点序列 / 日志        │
├──────────────────────────────────────────────────────────────────────────┤
│  L4  操作 Manipulation                  (5–30 Hz, GPU+CPU)                │
│      目标检测分割 → 6D位姿 → 抓取规划 → 操作策略(VLA/模仿学习) → 双臂协调  │
├──────────────────────────────────────────────────────────────────────────┤
│  L3  导航 Navigation                    (10–50 Hz, CPU+GPU)               │
│      全局中心线跟踪 / 地形代价图 / 局部避障 / 边界硬约束 / 落脚点规划      │
├──────────────────────────────────────────────────────────────────────────┤
│  L2  运动控制 Locomotion                (200–500 Hz, 实时CPU)             │
│      WBC(质心+ZMP+足底力) / 步态调度(6类) / 跌倒恢复FSM / 打滑恢复         │
├──────────────────────────────────────────────────────────────────────────┤
│  L1  状态估计 State Estimation          (200–500 Hz, 实时CPU)             │
│      躯干位姿速度 / 地形高度图 / 接触与打滑检测 / 全局定位(GNSS+SLAM)      │
├──────────────────────────────────────────────────────────────────────────┤
│  L0  硬件抽象 HAL                       (500–1000 Hz, MCU/驱动)           │
│      关节伺服 / IMU / 足底力 / 电池BMS / 定位模块 / 急停                  │
└──────────────────────────────────────────────────────────────────────────┘
       横切 A：安全与故障 Safety & Fault (看门狗 / 分级降级 / 缓慢卸力)
       横切 B：裁判接口 Judge I/F      (状态码上报 / 轨迹上报 / 全程日志落盘)
```

### 1.1 频率解耦原则（最重要的一条工程纪律）

| 层 | 频率 | 载体 | 隔离要求 |
|---|---|---|---|
| L0–L2 | 200–1000 Hz | **独立 MCU / PREEMPT_RT 隔离核** | 独占 CPU，禁止被 GPU 任务阻塞 |
| L1 地形图 / L3 | 10–50 Hz | GPU + 普通核 | 通过无锁环形缓冲与 L2 交换 |
| L4 操作策略 | 5–30 Hz | GPU 独占 | 只在"操作相位"激活，行走时挂起 |
| L5 编排 | 1–5 Hz | 普通核 | 唯一有全局状态的地方 |

> ❌ 反面案例：把 VLA 推理和关节伺服放在同一个 Python 进程里 → 推理一卡，机器人就摔。
> ✅ 正确做法：实时域（ros2_control + 自研 RT 控制器）与非实时域（感知/策略/编排）**物理隔离**，
> 用共享内存 + 无锁队列通信，实时域**永不阻塞**。

### 1.2 软件栈建议

| 层 | 选型 |
|---|---|
| 中间件 | ROS 2（Humble/Iron+，`preempt_rt` + `cpu_isolation`）；实时域走自研 RT 线程或 OROCOS |
| 仿真 | **Isaac Lab / Isaac Sim**（RL 训练 + 域随机化）；MuJoCo 做快速验证 |
| RL 框架 | Isaac Lab + RSL-RL / rl_games；策略导出为 TorchScript/ONNX |
| 操作学习 | LeRobot / ACT / Diffusion Policy；抓取用 GraspNet 或 AnyGrasp |
| 感知 | TensorRT 部署；检测分割 YOLO-Seg / SAM 轻量版；位姿 FoundationPose |
| 视觉里程计/SLAM | FAST-LIO2（LiDAR-惯导）或 OpenVINS/DPVO（视觉） |
| 日志 | rosbag2 + 结构化 JSONL（决策事件/干预事件/故障事件） |

## 二、L1 状态估计

### 2.1 模块清单

| 模块 | 输出 | 频率 | 方法 |
|---|---|---|---|
| 躯干状态估计 | 位姿、线/角速度 | 500 Hz | IMU + 腿部运动学（浮动基座 EKF） |
| 接触与打滑检测 | 每足接触概率、打滑标志 | 500 Hz | **足底力传感器** + 关节电流 + 足端速度残差 |
| 地形高度估计 | **2.5D Elevation Map** | 20–30 Hz | 深度图/LiDAR 点云投影滤波 + 惯性滚动更新 |
| 可通行性代价 | 通行代价 + 危险区掩码 | 20 Hz | 高度图 → 坡度/台阶高度/粗糙度 → 代价 |
| 全局定位 | 赛道坐标系下的位姿 | 20–50 Hz | GNSS+IMU EKF；遮挡时 LiDAR-惯导里程计（FAST-LIO2）+ 回环 |
| 打卡点识别 | 打卡点 ID + 相对位姿 | 10 Hz | 视觉检测（标志物/二维码/特征），与地图匹配 |

> **条款锚点**：地形高度估计是 2.1 明文要求；边界检测是 2.1 明文要求；"区分可通行区域/障碍物/危险区"
> 是机器狗章 2.2.1 的表述，但人形章 2.1.2 要求"检测赛道障碍物、边界，不冲出赛道" → 等价地需要可通行性代价。

### 2.2 地形高度图的关键细节

- **必须做"脚底以下的洞"的处理**：斜坡下坡、台阶边缘、浅坑 → 高度图的负向不连续要显式标记为"跌落风险"，而不是简单插值。
- **坡度估计用 3×3 或 5×5 邻域平面拟合**，输出坡度角 + 台阶高度 + 粗糙度（高度方差）。
- **危险区掩码**：坡度 > 阈值、台阶高 > 越障能力、粗糙度 > 阈值 → 标为不可通行，直接进 L3 的硬约束。

## 三、L2 运动控制（工程重心）

### 3.1 控制栈

```
             ┌─ 步态调度 Gait Scheduler ────────────────────────┐
             │  平地快走 / 碎石崎岖 / 跨障 / 上下坡 / 台阶 / 恢复 │
             └──────────────────┬───────────────────────────────┘
                                ↓ 接触序列 + 速度指令
   L3 速度/落脚点  ──→  ┌─ MPC（质心轨迹 + ZMP 约束）──────────────┐
                        │  预测时域 0.5–1.0 s, 步长自适应            │
                        └──────────────┬──────────────────────────┘
                                       ↓ 期望质心轨迹 + 期望接触力
                        ┌─ WBC（全身控制，QP）──────────────────────┐
                        │  变量：全身关节加速度/力矩                  │
                        │  任务：质心跟踪 / 躯干姿态 / 摆动足轨迹 /   │
                        │        接触力分配 / 关节限位 / 力矩限幅     │
                        │  约束：ZMP inside support / 摩擦锥 / 力矩   │
                        └──────────────┬──────────────────────────┘
                                       ↓ 关节力矩
                        ┌─ 关节伺服（力矩模式）────────────────────┐
                        │  力矩限幅 / 冲击保护 / 温度降额 / 堵转检测  │
                        └──────────────────────────────────────────┘
```

**关键选择：WBC 用 QP 做力分配，RL 策略作为"高层步态生成器"而不是直接输出力矩。**

### 3.2 双路线并行（推荐）

| 路线 | 内容 | 优点 | 缺点 | 用途 |
|---|---|---|---|---|
| **A. 模型基** MPC + WBC | 传统最优控制 | 可解释、稳定、易调、ZMP 显式约束 | 复杂地形适应性弱 | **底盘安全网**（保底不摔） |
| **B. 学习基** RL 策略 | Isaac Lab 训练，域随机化 | 复杂地形/碎石适应性强、速度快 | sim2real gap、黑盒 | **性能上限**（拿高分） |

> **务必两条都有。** 路线 A 是"零干预"的保险（5.4 的 16 分 + 5.3 的 6 分），
> 路线 B 是"速度/崎岖地形"的得分上限（时间分 + 任务 1 完全通过）。
> 现场可切换：B 失效 → 立即降级到 A，**而不是等人干预**（一旦干预，−2 且可能降自主等级）。

### 3.3 六类步态的验收标准（对应第三章 3）

| 步态 | 触发条件 | 验收标准 | 对映评分 |
|---|---|---|---|
| 平地快走 | 通行代价低、坡度 <5° | ≥1.0 m/s 稳定，躯干水平 | 时间分 |
| 平地慢走 | 窄道 / 边界近 / 姿态需求 | 1.2 m 宽道不越界 | 4.4 边界、扣分项 2 |
| 碎石崎岖 | 粗糙度高、粒径 10–40 mm | 足底打滑后 1 步内恢复 | 任务 1、5.3 姿态 |
| 跨障 | 障碍高 60–100 mm | 单次跨过不碰倒（不"破坏场地"） | 障碍 4、扣分项 3 |
| 上下坡 | 坡度 10–15° | 上坡不倒退；**下坡不前倾失稳** | 障碍 2 |
| 台阶 | 3–5 级，单级 ≤100 mm | 连续上/下，无单足踩空 | 障碍 3 |
| **跌倒恢复** | 姿态异常 + 无法自稳 | **趴/仰/侧 → 站立 ≤3 s** | **5.3 稳定性 6 分** |

### 3.4 跌倒恢复专用设计（最高优先级）

不放在 RL 里黑盒训练，而是**独立的、可验证的有限状态机**：

```
IDLE ──(姿态判据: 躯干俯仰/横滚超阈值 且 触地)──→ DETECT
DETECT ──(判定姿态类别: 趴/仰/侧翻)──→ PLAN
PLAN ──(选择恢复动作序列)──→ EXECUTE
EXECUTE ──(每 100 ms 检查进度)──┬─(进度正常)──→ 继续
                                ├─(卡住)──→ RETRY_ALT（换动作序列，最多 N 次）
                                └─(已站立)──→ STABILIZE
STABILIZE ──(站立稳定 1 s)──→ IDLE
```

**设计要点**

1. **姿态分类**：趴/仰/侧翻 各一套动作序列（对称性利用）。
2. **时延指标 ≤3 s（硬性，来自 5.3），设计目标 ≤2 s**，包含"检测到"到"稳定站立"。
3. **不依赖视觉**：用 IMU + 关节位置 + 足底力即可判别与执行 → 视觉失效（跌倒时相机可能被遮挡）也能恢复。
4. **多路面验证**：平底、斜坡、碎石、台阶上分别验证（交付材料 2 的视频要涵盖多种路面）。
5. **限制外摆**：6.2.1 要求"关节缓慢卸力，禁止剧烈甩动" → 恢复动作幅度受限，不能用大幅甩腿借力。
6. **摔倒次数预算**：5.3 允许"累计 ≤2 次摔倒 + 3 s 内自恢复"。**把 2 次当资源管理**，
   第 2 次摔倒后必须显著降低速度/提高保守度。

### 3.5 打滑与扰动的自主应对（对应 5.4 的感知应对 4 分）

| 扰动 | 检测 | 响应 | 可被裁判观察到的表现 |
|---|---|---|---|
| 足底打滑 | 足端速度残差 + 力突变 | 缩短该足支撑时长、重算落脚点 | 明显"顿一下再调整脚步" |
| 碎石移位 | 接触点力消失 | 原地试探 + 换落脚点 | 明显"试探性抬脚" |
| 障碍位置微调 | 地图与当前感知不一致 | 触发**局部重规划**，绕行 | **明显"停 0.3 s 后绕开"** |
| 路面塌陷/浅坑 | 高度图负向突变 | 急停该步 + 后退 + 换路 | 明显后退换路 |

> **⚠️ 主观分要求"可见性"**：裁判看录像/现场判断你"自主应对"了。
> 所以响应动作**要足够可辨识**，不要做得太快太顺滑以致看不出。
> 建议：重规划时让躯干有一个明确的小停顿 + 头部朝向变化 → 人类能读懂"它在思考"。

## 四、L3 导航

### 4.1 全局：赛道中心线 + 打卡点序列

- 赛道 50–100 m、宽 1.2–2 m，有**中间打卡点**。
- 若允许赛前建图（第一章 1.3 提到"赛前完成…地图构建"）→ **务必利用**：
  2 分钟调试时间内做一次快速建图/定位初始化（见问题清单第 9 条，确认是否允许）。
- 打卡点识别：优先用**几何+视觉**双确认（标志物检测 + 里程计位置匹配），避免单模态误判。

### 4.2 局部：代价图 + 边界硬约束

```
代价 = w1·坡度代价 + w2·粗糙度代价 + w3·台阶高度代价
     + w4·静态障碍代价 + w5·动态障碍代价
     + w6·离中心线偏差代价
约束（硬，不可违反）：
     边界外 = ∞        ← 出界 −2/次，必须做成硬约束而非软惩罚
     不可通行区 = ∞
```

> **把边界做成"硬约束"而不是"高代价"**：软惩罚下最优化器仍可能选择贴边，
> 而 4.4 只要"任意部位持续越出"就判出界。窄道 1.2 m 时这一步是决定性的。

### 4.3 出界后的恢复行为（必须实现）

4.4 规定：出界 → "**需退回最近标记点**，并执行罚时"。

→ 这是一个**自主行为**，要写进状态机：
```
BOUNDARY_VIOLATION ──(裁判判定)──→ RETURN_TO_NEAREST_MARKER
   ──(沿已走过的路径反向行走 / 用里程计定位最近标记点)──→ 继续任务
```
> **不实现这个行为，被判出界后可能原地不动 → 被误判"已停止尝试" → 触发 5.7 无效成绩（0 分）。**

### 4.4 落脚点规划

- 输入：地形高度图 + 可通行代价 + 步态相位
- 输出：下一个摆动足的落点 + 落点高度
- 约束：落点坡度 < 阈值、台阶高 < 越障能力、距边界 > 安全裕量、足端可达性
- 参考方法：启发式候选点采样 + 代价最小化（或学习型落脚点打分网络）

## 五、L4 操作（48/60 任务分的来源）

### 5.1 五个任务的操作难度与方案

| # | 任务 | 感知需求 | 操作需求 | 推荐方案 | 目标档 |
|---|---|---|---|---|---|
| 1 | 密林穿越 | 地形高度图 | 无（纯行走） | L2+L3 | **12 分** ✅ 必拿 |
| 2 | 雷区侦察 | **颜色识别** + 引线定位 | 精确抓握 + 按序拔 | 手腕相机 + 视觉伺服 + 顺序解析 | 7→12 |
| 3 | 收纳急救物品 | 物品识别/分类 + 药箱口定位 | 抓取（多形状）+ 有序放置 | 语言条件序列 + 抓取规划 + 放置位姿优化 | 7→12 |
| 4 | 伤员转运 | **假人位姿估计** | 双臂抱起 + **负重行走** | 全身协调（质心补偿）+ 专用抱姿 | 7（12 极难） |
| 5 | 丛林投物 | 目标区定位 | 抓取 + **投掷动力学** | 学习型抛投策略（末端速度控制） | 7→12 |

### 5.2 任务 2（雷区侦察）技术方案

- **顺序实现**：从任务下发（语音/结构化清单）解析出 `[颜色1, 颜色2, ...]` 序列；
  用 VLM/OCR 或预设结构化输入 → 生成执行队列。
- **颜色识别**：HSV 阈值 + 深度定位（比学习模型更稳，颜色是低维信号）；光照变化用白平衡归一化。
  4.3 说"无强制补光" → **颜色识别必须对逆光/阴影鲁棒**，建议胸口/头部补一个**机载小补光灯**（不违规，属机载设备）。
- **拔线动作**：视觉伺服 → 末端对准引线 → 夹紧 → **沿引线方向匀速后拉**（避免扯断/扯动其他引线）。
- **顺序容错**：错误顺序 → 只降到 7 分。**策略：先保证"拔下每一根"，再优化顺序。**
  执行中若识别不确定 → 宁可先用保守多视角确认（但注意**不要产生 >5 s 非必要停顿**，否则流畅度扣分）。

### 5.3 任务 3（收纳）技术方案

- **有序收纳**：清单顺序 → 抓取队列；每步：识别目标物品 → 抓取 → 移到药箱上方 → 调整位姿 → 放入。
- **"整齐放入"的量化**：定义放置位姿容差 + 不超出箱口 + 不倾倒。
- **掉落自恢复（7 分保险）**：物品掉落是最可能发生的事故 → **必须实现"掉落检测 → 重新定位 → 自主拾取"**。
  这是 12→7 的保险，投入产出比极高。
- **分类**：若物品有类别（药品/绷带/器械）→ 用颜色/形状/标签（OCR）分类。

### 5.4 任务 4（伤员转运）技术方案 —— 最高风险

```
抱姿规划：双臂环抱腋下/腰背，假人贴近躯干（减小质心偏移）
全身协调：WBC 目标里加入"负载质心补偿"——把假人质量视为躯干附加质量，
          质心目标前移/后移，ZMP 约束收紧，步长缩短、速度降低
行走策略：慢速（0.3–0.5 m/s）+ 短步长 + 高抬脚裕量 + 加大横向稳定裕度
掉落恢复：检测负载消失（力/视觉）→ 停止 → 蹲下 → 重新抱起（7 分保险）
```

> **前提仍是假人质量**。若假人 >5 kg 且平台臂载 2–3 kg：
> **降级方案 = "拖拽式转运"**（双臂抓假人上肢/衣领，假人贴地拖行）。
> 这不算"抱起"，但**可能仍被判定"完成赛道通行"**→ 争取 7 分档而非 0 分。
> 采购前务必确认假人质量，这会反向影响平台选型（拖拽需要更大的腿力和更低的深蹲姿态）。

### 5.5 任务 5（丛林投物）技术方案

- 投掷 = 末端速度 + 释放时机的问题。
- 方案：学习型抛投（模仿学习/RL 训一个"抛到目标区"的策略）或 解析模型（抛体方程 + 逆运动学）。
- **目标区尺寸未知** → 先按"大目标区"训练（易命中），再按问题清单的回答收紧。
- 容错：允许"抛出圈外但完成投掷动作"= 7 分 → **先保证投掷动作成立**。

### 5.6 VLA 的定位（务实版本）

| 层级 | 用什么 | 频率 | 为什么 |
|---|---|---|---|
| 下肢运动 | RL 策略 + WBC | 200–1000 Hz | VLA 根本无法闭环 |
| 地形/避障 | 小型 CNN/TensorRT | 10–30 Hz | 确定性要求高 |
| **任务解析**（"按清单顺序…"） | **VLM/VLA 低频调用** | 0.2–1 Hz | 语言理解是 VLA 的强项，非实时可接受 |
| **操作技能**（拔线/抓取/投掷） | **ACT / Diffusion Policy** | 10–30 Hz | 参数量可放上机载，实时性可行 |
| 端到端 VLA 直接输出力矩 | ❌ 不做 | — | 延迟/显存/稳定性都不可行 |

> **一句话**：**用 VLA 做"理解"，用模仿学习做"动作"，用最优控制做"稳定"。**
> 三层各司其职，这既符合 2.1"感知–规划–控制"的架构表述，也是在 Orin 级算力上唯一可行的组合。

## 六、L5 任务编排（得分策略的落地处）

### 6.1 状态机（核心：不存在"放弃"状态）

```
INIT ─→ SELF_CHECK ─→ START_CMD(裁判发令) ─→ TASK_QUEUE
                                                 │
        ┌────────────────────────────────────────┘
        ↓
   EXEC_TASK[i] ──┬─(完成)──────────→ NEXT_TASK ──(全部完成)──→ FINISH ✅
                  ├─(受阻 > T_budget[i])──→ SKIP_AND_CONTINUE  ⚠️ 不是放弃！
                  ├─(摔倒)──→ FALL_RECOVERY ──(≤3s 站起)──→ EXEC_TASK[i]
                  │                              └─(重试 N 次失败)──→ "保持运动"
                  ├─(打滑/扰动)──→ REPLAN ──→ EXEC_TASK[i]
                  ├─(边界越出)──→ RETURN_TO_MARKER ──→ EXEC_TASK[i]
                  ├─(低电量)──→ 前往补给站换电（若允许）──→ EXEC_TASK[i]
                  └─(故障)──→ DEGRADE_MODE（降步态/降速）──→ 继续
                                        
   ⛔ 严禁的状态：GIVE_UP / WAIT_FOR_HUMAN / HALT
      （5.7 第 1 条："15 min 未完赛且已停止尝试" = 本轮 0 分）
```

### 6.2 时间预算表（以 10 分钟满分为目标）

| 阶段 | 预算 | 累计 |
|---|---|---|
| 起步自检 + 站立 | 20 s | 0:20 |
| 移动至任务 1（假设 15 m） | 25 s @0.6 m/s | 0:45 |
| 任务 1 密林穿越 | 90 s | 2:15 |
| 移动（15 m，含窄道减速） | 40 s | 2:55 |
| 任务 2 雷区侦察（4 根引线） | 90 s | 4:25 |
| 移动 | 30 s | 4:55 |
| 任务 3 收纳（4 件物品） | 120 s | 6:55 |
| 移动 | 30 s | 7:25 |
| 任务 4 伤员转运 | 100 s | 9:05 |
| 移动 | 25 s | 9:30 |
| 任务 5 投物 | 25 s | 9:55 |
| **合计** | | **≈ 10 min** |

> 表格说明两件事：
> 1. **时间预算非常紧**。任何一项超时都会掉到 8 分档。所以**每项的 `T_budget[i]` 要有硬上限**（见下表）。
> 2. **秒级精度决定 10 分 vs 8 分**。所以"减速靠停"和"任务点前定位"的耗时必须实测优化。

**单项超时上限（`T_budget[i]`）建议**

| 任务 | 硬上限 | 超出动作 |
|---|---|---|
| 1 密林穿越 | 120 s | 继续降速推进（不能跳过，是必经路线） |
| 2 雷区侦察 | 150 s | 跳过剩余引线 → 下一项（保住已完成的） |
| 3 收纳 | 180 s | 跳过剩余物品 → 下一项 |
| 4 伤员转运 | 150 s | 降级为拖拽 → 仍超时则跳过 |
| 5 投物 | 90 s | 完成投掷动作即可（拿 7 分档） |

### 6.3 降级策略（按优先级）

| 触发 | 降级 | 保住的分数 |
|---|---|---|
| 主策略失败 | 切换到保守策略（慢速模型基控制） | 保 16 自主分 + 6 稳定性分 |
| 操作抓取连续失败 | 换抓取位姿 → 换抓取点 → 跳过该子项 | 保"有条件通过"7 分 |
| 某任务整体失败 | **跳过并继续下一项** | 保其他任务分 + 时间分 + 自主分 |
| 电量低 | 前往补给站换电（若允许且计时） | 保续航与完赛 |
| 传感器部分失效 | 降级融合（去掉失效源）+ 降速 | 保 2.1.4"输出故障状态" + 继续完成任务 |

### 6.4 干预规则（把"零干预"变成工程约束）

| 情形 | 是否允许干预 | 处理 |
|---|---|---|
| 跌倒无法自恢复 | 允许，**但需经裁判许可** | 先自主重试 N 次（提高成功率），不行再叫裁判 |
| 电池耗尽 | 允许，需裁判许可 | 靠换电策略提前规避 |
| 其他任何情况 | ❌ 不允许（2.1 禁止实时遥控） | 必须自主降级 |

> **全自主组的物理隔离建议**（防"手滑"导致自主等级降到 4 分）：
> - 操作台**不接**运动控制手柄（把降级路径物理堵死）
> - 遥控器只保留**急停**按钮
> - 必须发的指令限定为"**分阶段远程启停**"（落在半自 10 分定义内，损失 6 分而非 12 分）

## 七、横切 A：安全与故障

### 7.1 故障分级（参照机器狗章 6.1 的思路，人形章 6 要求输出故障状态）

| 级别 | 判据 | 响应 |
|---|---|---|
| 轻度 | 单传感器失效（如 1 路相机/1 个足底力） | 降级融合，限速继续任务，上报故障码 |
| 中度 | 打滑频发 / 关节温度高 / 电流异常 | 降速、改步态、缩短任务步数 |
| 重度 | 电池告警 / 关节异常 / 姿态失控 | **原地自主停机 + 上报**（不是等人） |
| 紧急 | 冒烟/异响/失控 | 硬件急停（裁判亦可远程急停） |

### 7.2 急停合规序列（6.2.1："关节缓慢卸力，禁止剧烈甩动"）

```
急停触发
  → (0 ms)   停止新运动指令，冻结 L5/L4/L3
  → (0–300 ms) 步态切入"缓慢下蹲"：髋膝踝协调，质心按受限速率下降
  → (300–1500 ms) 达到稳定低姿（跪姿/坐姿），力矩逐渐降至支撑所需
  → (>1500 ms) 若仍不动 → 断开动力（硬件接触器）
  ❌ 绝不直接断电：无支撑质量的人形会"砸"到地面 → 可能损坏 + 违反"禁止剧烈甩动"
```

### 7.3 看门狗

- 每层独立看门狗；实时域超时 → 回退到 MPC/WBC 安全策略（不是停机）
- 通信中断（与地面站）→ **不影响比赛**（1.1 禁线缆，2.1.5 禁遥控指令 → 地面站本就非必需）
- 视觉中断 → 切换到"盲走 + 足底力反馈"降级步态

## 八、横切 B：裁判接口与数据留存

### 8.1 状态码上报（第三章 3 明文要求）

| 状态码 | 含义 | 上报时机 |
|---|---|---|
| `NORMAL_WALK` | 正常行走 | 平地/斜坡常规步态 |
| `OBSTACLE_CROSS` | 越障中 | 跨障/台阶/跳跃 |
| `FALLEN` | 跌倒 | 检测到跌倒（含恢复中） |
| `FAULT` | 故障 | 任一重度故障 |
| `LOW_BATTERY` | 低电量 | 电量低于阈值 |

**实现要点**

- 上报通道：与定位模块共用一条**无线**链路（2.1.5 只禁图像下行与运动指令下行，状态上行是允许且必需的）。
- 延迟 < 200 ms；断连时本地缓存、恢复后补传。
- **同时在本机屏幕上大字显示** → 质检裁判/旁观者一眼可见（这也是"传感器功能验证"的展示窗口）。

### 8.2 轨迹上报（1.3.4 明文要求）

- 赛事指定定位模块（北斗/惯导）→ 轨迹实时回传裁判系统。
- **需先向组委会索取接口协议**（问题清单第 10 条），可能与状态码是同一条链路。
- **自采一份轨迹**作备份：若裁判系统数据异常，自己的日志是申诉证据。

### 8.3 全程日志落盘（7.2 明文要求）

| 日志类别 | 内容 | 频率 |
|---|---|---|
| 状态日志 | 时间戳、位置、姿态、关节状态、状态码 | 100 Hz |
| 决策日志 | 任务切换、重规划、降级触发、跳过决策 | 事件驱动 |
| 故障日志 | 故障码、传感器失效、打滑、温度告警 | 事件驱动 |
| **干预日志** | 干预时间、类型、见证裁判、影响任务 | 事件驱动 ← **申诉关键** |
| 感知记录 | 关键帧图像（本地存，不上传）× 低采样 | 1–2 Hz |

> **存储要求**：单轮 ≥2 小时容量；**掉电不丢**（fsync 或预分配 + 循环覆盖的可靠实现）。
> 这是"赛后提交运行日志用于成绩复核"的交付义务，也是自证清白的唯一手段。

## 九、仿真与 sim2real 路线

### 9.1 数字孪生（**按实测尺寸建模**）

必须 1:1 复刻的赛道元素：碎石（粒径 10–40 mm 分布）、斜坡（10/12/15°）、台阶（3/4/5 级 × 高度）、
跨障栏（60/80/100 mm）、颠簸路面（木板/垫块尺寸）、窄道（1.2 m）、弯道、梅花桩/浅坑（若有）。

> **不要用"差不多"的尺寸建模**：障碍尺寸直接决定步态参数与越障能力，
> 差 20 mm 就可能让训练好的策略在真机失效。

### 9.2 域随机化（Domain Randomization）清单

| 随机化项 | 范围 | 目的 |
|---|---|---|
| 地面摩擦系数 | 0.3–1.2 | 碎石/湿滑 |
| 质量与质心 | ±10% 机身 + ±(载重) | 负载不确定性 |
| 关节力矩/延迟 | ±15% / 0–10 ms | 驱动器差异 |
| 传感器噪声与偏置 | IMU/力/编码器 | 标定误差 |
| 地形粗糙度 | 高度噪声 0–30 mm | 碎石 |
| 外部推力 | 随机方向 0–40 N | 落地冲击/扰动 |
| 电池电压衰减 | 额定 → 低电 | 后半程功率下降 |

### 9.3 sim2real 验收门槛

| 指标 | 仿真 | 真机门槛 |
|---|---|---|
| 平地速度 | 1.5 m/s | ≥1.0 m/s |
| 越障高度 | 150 mm | ≥120 mm |
| 坡度 | 20° | ≥18°（下坡也要） |
| 跌倒恢复 | 1.5 s | **≤3 s（硬性）** |
| 打滑恢复 | 1 步 | ≤2 步 |

> 仿真指标要显著高于真机门槛，因为 sim2real 一定有衰减（经验值打 7–8 折）。
